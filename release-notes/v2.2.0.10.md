# INVminer v2.2.0.10

Proxima upgrade-6 · Linux / HiveOS / Windows x64 · 0% developer fee.

## Changes

- Faster GPU search and result handling on supported NVIDIA GPUs; measured gains over 2.2.0.9 are listed below. No pool update or new tuning flag is required.
- Correct GPU active-time accounting when two batches are queued. This fixes an auxiliary rate calculation; it does not multiply completed work or pool shares.

## Measured performance / 实测算力

Final release executables versus 2.2.0.9 on the current InnovLab pool, using the same physical GPU, power cap and ordered Asia endpoints. A/B/B/A, 60 seconds warmup per phase; all subsequent wall time and job gaps included. Units: GH/s. These are completed nonce attempts per second, with Accepted receipts reconciled to the pool; they are not earnings forecasts or statistically precise share-rate estimates.

| GPU | OS / driver | Power cap | 2.2.0.9 | 2.2.0.10 | Observed change |
|---|---|---:|---:|---:|---|
| RTX 4090 | Linux / 595.71.05 | 450 W | 12.876 | 13.347 | **+3.66%** |
| A100 SXM4 40GB | Linux / 595.91.07 | 225 W | 4.457 | 5.499 | **+23.37%** |
| CMP 50HX | HiveOS / 610.43.03 | 160 W | 3.417 | 3.463 | **+1.34%** |
| CMP 40HX | HiveOS / 610.43.03 | 110 W | 2.067 | 2.068 | +0.04%; essentially unchanged; baseline drift 3.19% |
| RTX 3070 Ti | Windows / 536.40 | 100 W | 1.205 | 1.177 | −2.36% raw; baseline drift 3.44%, not a qualified speedup |

4090 and A100: four 420-second phases each. CMP cards: four 240-second phases each. The 4090 candidate had one stale share; the A100 baseline had one stale share. These samples do not establish long-term stability or equal gains on other drivers, power settings or GPUs.

RTX 5060 Ti completed real mining with the final binary, but its comparison was interrupted by a test-host reboot during the old-version phase. No completed A/B/B/A uplift is claimed for it. No new final-package performance result is claimed for 3090, 4070 SUPER, 5090 or RTX PRO 5000 in this release.

Windows: four 180-second phases; 184 Accepted matched the pool, zero rejected/stale. The changing baseline prevents attributing the raw difference to the release. No Windows performance improvement is claimed.

Windows RTX 3070 Ti was tested at the owner's unchanged 100W cap with driver 536.40. Linux gains are not Windows promises. HiveOS validation used the actual custom-get installer and local flight-sheet callbacks, including upgrade and restart; the HiveOS cloud UI was not operated.

本表为当前实池、最终发布程序相对 2.2.0.9 的同卡交替对照，不需要矿池升级。保留任务空档、过期份额和低提升结果，不宣传所有显卡都有 5% 提升。5060 Ti 已实挖，但整轮对照因测试机重启中断，未给出完整验证的提升比例。Windows 与其他未完成本版性能复验的卡型不套用 Linux 数据。

## Recommended pools / 多池推荐参数

Ordered multiple pools, automatic reconnect, primary recovery and `rotate` remain supported. Keep this order; repeat `-o` on Linux, or enter one URL per line in HiveOS.

| Region / 区域 | Primary / 主池 | Backup 1 / 备用一 | Backup 2 / 备用二 |
|---|---|---|---|
| Asia / 亚洲 | `stratum+ssl://fast-hk1.innovlab.cc:19701` | `stratum+ssl://fast-hk2.innovlab.cc:19701` | `stratum+ssl://hk.innovlab.cc:19701` |
| Europe / 欧洲 | `stratum+ssl://fast1-ru.innovlab.cc:19701` | `stratum+ssl://fast2-ru.innovlab.cc:19701` | `stratum+ssl://eu3.innovlab.cc:19701` |

```bash
./invminer --coin proxima \
  -o stratum+ssl://fast-hk1.innovlab.cc:19701 \
  -o stratum+ssl://fast-hk2.innovlab.cc:19701 \
  -o stratum+ssl://hk.innovlab.cc:19701 \
  -u YOUR_PROXIMA_HOLDER_ID.WORKER -p x \
  --pool-failover-mode primary --pool-give-up-limit 3 \
  --pool-probe-interval-secs 60 --pool-probe-successes 2
```

The four failover options above restate the defaults. `primary` returns to the preferred pool after successful login/job probes, subject to failure cooldowns. `--pool-failover-mode rotate` stays on a healthy backup and advances when it fails. Multiple entries provide fallback, not simultaneous mining. Mining TLS is encrypted and accepts self-signed pool certificates; download HTTPS verification remains enabled.

以上切换参数即默认值，通常无需额外调整。`primary` 会探测并恢复首选池；`rotate` 在备用池健康时继续挖，不主动切回。多个地址用于故障切换，不是同时挖多个池。

All six listed endpoints received valid shares during final-package qualification. An earlier EU3 test timed out from a Chinese test route and successfully fell back; the direct retest passed. This is functional verification, not an availability or latency guarantee.

Windows: extract the ZIP and run `start-proxima.bat`. Asia is the default; for Europe:

```bat
start-proxima.bat -Account YOUR_PROXIMA_HOLDER_ID -Worker WORKER -Region europe
```
