# INVminer v2.2.0.3

## Changes

- Reduce Proxima CPU usage while waiting for GPU work; enabled by default, with no new configuration argument.

## Compatibility

**Proxima upgrade-6 only, 0% developer fee.** NOID/QUAN users should keep their existing package. The pool protocol, command-line arguments and flight-sheet fields remain compatible with 2.2.0.2. Change only the installation URL when upgrading. Existing clock and power settings are preserved.

## CPU usage and tested GPU hashrates / CPU 占用与已测试显卡算力

On the same two-logical-CPU rig with four CMP 40HX cards, an old/new/new/old comparison against 2.2.0.2 measured:

| Measurement | 2.2.0.2 | 2.2.0.3 |
|---|---:|---:|
| Miner process CPU (one logical CPU = 100%) | 194.55% | 9.67% |
| Four-card completed-work hashrate | 7.857 GH/s | 7.930 GH/s |

CPU usage fell **95.03%**. Completed-work hashrate changed **+0.92%**; this short comparison found no throughput loss, but the small positive difference is not a guaranteed speed gain. Each old/new phase ran 150 seconds, excluding its first 30 seconds; the two new measurement windows totaled 236.65 seconds.

All rates below use completed nonce attempts divided by elapsed wall time, measured with the final public executables. Power limits are configured caps, not measured consumption.

| GPU | Cards | CUDA | Driver | Power limit/card | Measured window | Per-card hashrate |
|---|---:|---:|---|---:|---:|---:|
| NVIDIA CMP 40HX | 4 | 12 | 580.173.02 | 125 W | 236.65 s total | 2.006 / 2.004 / 1.957 / 1.963 GH/s |
| NVIDIA CMP 40HX | same 4 | 13 | 580.173.02 | 125 W | 58.18 s | 2.019 / 2.019 / 1.966 / 1.979 GH/s |
| NVIDIA GeForce RTX 4070 SUPER | 6 | 12 | 535.171.04 | 220 W | 95.44 / 65.63 s | 5.389–5.516 / 5.448–5.583 GH/s |

The two six-card RTX 4070 SUPER runs totaled **32.635 / 33.003 GH/s**, excluding the first 25 seconds of each run. Those are rig totals, not single-card rates. The CUDA 13 CMP run excluded its first 30 seconds. Short live-pool samples vary with tasks, clocks, temperatures and transport latency; they do not establish long-term stability, earnings or performance on other models. Stale outcomes were retained and are excluded from Accepted counts. The GPU kernels are unchanged from 2.2.0.2; historical results for other cards are not relabeled as tests of this version.

本次修改默认降低 GPU 等待阶段的 CPU 消耗，不需要调超频或新增参数。四卡 CMP40HX 同机交替对照未发现算力损失；表内均为本次公开制品实测，不外推未测型号。

## GPU command

```bash
./invminer --coin proxima -o stratum+ssl://global.innovlab.cc:19701 -o stratum+ssl://eu3.innovlab.cc:19701 -u YOUR_PROXIMA_HOLDER_ID.WORKER
```

Use your registered 64-hex holder/account ID. The worker suffix and password are optional; an omitted password uses `x`. All visible supported GPUs are selected by default; use `--devices 0,2` for a subset.

Ordered endpoints, reconnects, primary recovery and `rotate` are retained. Default `primary` mode probes the first endpoint and returns after successful probes. Add `--pool-failover-mode rotate` to remain on a healthy backup until it fails. Mining uses one active Stratum connection, with no separate Python seeker or prox-agent.

## HiveOS flight sheet

- Miner: Custom → `invminer`
- Installation URL: `https://github.com/getrigeos/INVminer-Release/releases/download/v2.2.0.3/invminer-2.2.0.3.tar.gz`
- Coin: Custom / PROX
- Hash algorithm: `proxima`
- Wallet: your registered Proxima holder/account ID
- Wallet template: `%WAL%.%WORKER_NAME%`
- Pool URLs: keep your current ordered endpoints; public examples are `stratum+ssl://global.innovlab.cc:19701` and `stratum+ssl://eu3.innovlab.cc:19701` (one per line, or comma-separated)
- Pass: optional; default `x`
- Extra config arguments: `--coin proxima`

Real HiveOS qualification covered the official custom-miner installer, upgrading from 2.2.0.2, restart, all six GPUs, per-GPU Accepted and statistics. Cloud flight-sheet UI operation was not part of this test.

Linux x86_64 and glibc 2.31+ are required. CUDA 12 needs CUDA Driver API 12.0+; RTX 50-series needs a suitable R570+ driver. CUDA 13 needs Driver API 13.0+ (R580+). Mining TLS stays encrypted without requiring server-certificate verification; download HTTPS verification remains enabled.
