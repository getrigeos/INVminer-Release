# INVminer NOID GPU Miner v0.1.45

This release hardens long-running NOID operation without changing the reviewed
CUDA mining kernels, work allocation or pool protocol. It adds a professional
120-second status panel, loopback JSON/Prometheus monitoring, per-device share
accounting, bounded recovery, continuous thermal protection, bounded log
rotation and persistent developer-fee schedule state.

Both packages are multi-architecture Linux x86_64 binaries; choose by host
driver compatibility, not GPU model. No proprietary Rust/CUDA or
hardware-control source is included in these archives or this public
repository.

> **Binary-only risk:** this release may be incompatible with a particular GPU,
> driver, OS or pool state. Source is not provided, so users cannot independently
> rebuild, audit or patch it and must decide whether to trust the binary and its
> published checksums.

## Recommended command

All visible GPUs, recommended:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --state-dir /var/lib/invminer
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0 \
  --state-dir /var/lib/invminer
```

The state directory must be persistent for managed services and containers.
Do not provide threads, nonces-per-thread or batch parameters. Qualified models
select reviewed defaults; other supported models perform a bounded first-run
auto-tune and save it locally.

Optional RTX 4090 profile:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0 \
  --state-dir /var/lib/invminer \
  --power-limit 450 \
  --locked-core-clock 2400
```

Default clocks remain the general recommendation. Hardware controls are
optional; an unsupported operation warns and continues at verified defaults.
Locked-core and offset tuning should not be combined without card-specific
qualification.

## GPU measurements and compatibility evidence

Hashrate is the miner's NOID work rate. The exact v0.1.45 RTX 4090 benchmark
rows used no miner hardware-control arguments, factory 450 W power limit and a
30-second steady measurement. Average/peak power includes only samples at
least 95% GPU utilization.

| GPU | SM | Package / driver | Evidence status | Hashrate | Power limit | Average / peak power | Clock/control state |
|---|---|---|---|---:|---:|---:|---|
| RTX 3080 | `sm_86` | CUDA 12 / 550.78 | Reused frozen-lane physical evidence | `42.001 MH/s` | `320 W` | `279.67 / 284.37 W` | default clocks |
| RTX 4070 SUPER ×6 | `sm_89` | CUDA 12 / 535.171.04 | Reused frozen-lane multi-GPU evidence | `53.450 MH/s/GPU`; `320.701 MH/s` aggregate | `220 W/GPU` | `219.51 W/GPU` aggregate average; `220.55 W` peak individual | default clocks |
| RTX 4090 | `sm_89` | CUDA 12 / 580.173.02 | Exact packaged v0.1.45 benchmark | `114.964 MH/s` total; `114.986 MH/s` kernel | `450 W` | `421.16 / 438.38 W` | no miner hardware-control arguments |
| RTX 4090 | `sm_89` | CUDA 13 / 580.173.02 | Exact packaged v0.1.45 benchmark | `112.006 MH/s` total; `112.018 MH/s` kernel | `450 W` | `402.39 / 408.98 W` | no miner hardware-control arguments |
| RTX 5090 | `sm_120` | CUDA 13 / 595.84 | Reused frozen-lane physical evidence | `159.135 MH/s` | `575 W` | `549.04 / 564.70 W` | default clocks |

The RTX 4070 SUPER per-card figure is the six-card aggregate divided by six;
the peak is the highest individual card sample. All six cards used one shared
user-pool connection and disjoint search allocation. Reused rows are not
presented as v0.1.45 host-binary reruns: their native CUDA modules are
byte-identical to the reviewed v0.1.45 lanes, but runtime and host conditions
were not requalified for this release.

4090 performance varies with firmware, driver, cooling, virtualization and
power behavior. These results are evidence for the listed host, not a universal
card promise.

## Reliability and monitoring

- The exact CUDA 13 package obtained 97 accepted, 3 stale and 0 rejected shares
  in the final live gate. The stale total includes a deliberately severed TCP
  session.
- After the only pool socket was forcibly closed, the process remained alive,
  reconnected once, returned to `112.477 MH/s`, and continued accepting shares.
- The production InnovLab edge was TLS-unavailable during the final gate, so
  the authorized WebPKI-verified `release-gate-compat` path was used. Its
  endpoint identity is intentionally not published.
- `/stats` and `/metrics` are bound to `127.0.0.1:4068`; both expose aggregate
  and per-device accepted/stale/rejected counters. They are not a public API.
- Continuous per-device thermal control limits at 92 C and pauses at 95 C,
  with hysteretic automatic recovery. Stale temperature sensors pause only the
  affected device.
- Returned CUDA errors rebuild the affected device with bounded backoff. Three
  exhausted rebuild attempts exit nonzero so an unlimited-restart service can
  create a fresh driver context. An in-flight progress watchdog covers a hung
  synchronous CUDA call.
- Pool reconnect uses bounded exponential backoff with jitter. Share health
  requires at least 20 consecutive resolved rejections or a majority of a full
  100-response window; stale and expired responses do not count as rejects.
- Runtime logs are bounded and rate-limited. Per-share/per-job hot-path logs,
  exact developer-fee transitions and payout identities are absent.

## Developer fee

The compiled developer fee is 5% of effective GPU mining time under a 95/5
cycle. The initial phase and integrity-checked progress are persisted under the
state directory, so process restarts neither reset nor front-load the schedule.
Waiting, preparation failure and unavailable fee work are not charged. The
payout destination is embedded and intentionally absent from public material
and normal runtime logs. User and fee raw share counts need not form a 95:5
ratio when their sessions receive different difficulties.

## Validation summary

- CUDA 12 passed 52 release tests; CUDA 13 passed 53. Both passed formatting
  and strict Clippy with warnings denied.
- Two independent clean builds of each flavor matched byte-for-byte.
- CPU/GPU exact vectors and search-result self-tests ran before GPU work.
- SM86, SM89 and SM120 reviewed module hashes are unchanged from v0.1.44.
- Version, archive members, GLIBC ceiling, private paths, credentials, legacy
  branding, developer-fee identity/timing templates and high-rate log templates
  passed static gates.
- Persistent fee state loaded cleanly after a real process restart.
- The original workload on the RTX 4090 gate host was restored after testing.

The CUDA 12 host package embeds the reviewed native `sm_120` module produced by
the CUDA 13 toolchain because CUDA 12 cannot assemble that instruction path. It
links no CUDA 13 runtime and remains the broad host-compatibility package.
