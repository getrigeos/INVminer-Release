# INVminer v0.1.63

## GPU command

```bash
./invminer --coin noid \
  -o stratum+ssl://eu.innovlab.cc:19601 \
  -u YOUR_NOID_ADDRESS.RIG_NAME
```

Use only an official NOID TLS endpoint: `eu.innovlab.cc:19601` (Europe) or
`hk.innovlab.cc:19601` (Hong Kong). This example defaults to Europe; replace
only the hostname to use Hong Kong. `-p/--pass` is optional; omission uses the
compatible default value `x`.

## CPU-only command

```bash
./invminer --coin noid --cpu-only \
  -o stratum+ssl://eu.innovlab.cc:19601 \
  -u YOUR_NOID_ADDRESS.RIG_NAME
```

> **Binary-only risk:** this release may not work with every GPU, CPU, driver,
> OS, or future pool state. Source is not provided here, so users cannot
> independently rebuild, audit, or patch it and must decide whether to trust
> the executable and published checksums. The software is provided without
> warranty.

## Ampere qualification update

This release adds an automatically selected execution profile for the exact
RTX 3080 10GB model on current drivers. Other GPU-model and architecture
selections remain unchanged. The CUDA 12/HiveOS flavor retains its reviewed
primary SM86 image, older-driver native image, and embedded CUDA 12.2 native
SM86 compatibility fallback; selection is automatic and requires no module or
geometry setting.

The password option remains optional for CLI, JSON, and HiveOS use. An omitted
CLI password or empty HiveOS Pass uses `x`. User-pool login also carries bounded
GPU-summary and miner-version metadata; pools that ignore the optional metadata
remain compatible.

## Validated RTX 3080 sample profile

The following profile was validated on the qualified RTX 3080 10GB sample with
NVIDIA Linux driver 580.178.04. It uses no core lock; the memory lock and core
offset are applied by INVminer:

```bash
./invminer --coin noid --devices 0 \
  --power-limit 320 \
  --lock-mem 810 \
  --core-clock-offset 260 \
  --nvidia-display :0 \
  --nvidia-xauthority /var/run/lightdm/root/:0 \
  -o stratum+ssl://eu.innovlab.cc:19601 \
  -u YOUR_NOID_ADDRESS.RIG_NAME
```

On the qualified RTX 3080 10GB sample, a warm 60-second run at the 320 W power cap produced 64.386 MH/s.

The offset is sample-specific and is not guaranteed on every RTX 3080. If an
optional setting cannot be applied, INVminer warns, restores the affected
hardware state, and continues at verified defaults when safe.

## Native NVIDIA controls

The existing `--power-limit`, `--lock-core`, `--locked-core-clock`,
`--lock-mem`, and `--core-clock-offset` controls are retained. Unsupported
values, missing permissions, or unavailable optional tools produce a warning
and mining continues at the verified original/default state; an unsafe partial
rollback stops mining.

## HiveOS

- Miner name: `invminer`
- Installation URL: `https://github.com/getrigeos/INVminer-Release/releases/download/v0.1.63/invminer-0.1.63.tar.gz`
- Hash algorithm: `noid`
- Pool URL: `stratum+ssl://eu.innovlab.cc:19601`
- Wallet and worker template: `%WAL%.%WORKER_NAME%`
- Pass: leave empty (or enter `x`; both use the compatible default)
- Extra config arguments: leave empty unless ordinary runtime options are needed

The HiveOS archive must remain `<miner-name>-<version>.tar.gz`; do not add the
tag `v`, platform, architecture, HiveOS, or CUDA labels.

### Manual upgrade for older HiveOS installations

Only some older HiveOS installations need this manual replacement. Use it only when HiveOS does not update the installed custom miner after the Installation URL is changed to this release.

```bash
miner stop && cd /tmp && rm -rf invminer && rm -f invminer-0.1.63.tar.gz && wget -O invminer-0.1.63.tar.gz https://github.com/getrigeos/INVminer-Release/releases/download/v0.1.63/invminer-0.1.63.tar.gz && tar -xzf invminer-0.1.63.tar.gz && mkdir -p /hive/miners/custom/invminer && rm -f /hive/miners/custom/invminer/invminer && cp -af invminer/. /hive/miners/custom/invminer/ && chmod +x /hive/miners/custom/invminer/invminer /hive/miners/custom/invminer/h-*.sh && /hive/miners/custom/invminer/invminer --version && miner start
```

### 舊版 HiveOS 手動升級

僅部分舊版 HiveOS 需要此手動覆蓋；只有在更新 Installation URL 後仍未替換已安裝的 Custom Miner 時才執行。

## Developer fee and startup boundary

NOID uses a 5% developer fee measured from effective mining time. Waiting,
connection preparation failures, and unavailable fee work are not charged.
Extracting or running the package does not install or enable a boot service,
cron job, scheduled task, login/startup item, or container restart policy.

# INVminer v0.1.63（繁體中文）

本版為目前驅動上的 RTX 3080 10GB 精確型號加入自動選擇的執行設定；其他 GPU 型號與架構
選擇維持不變。CUDA 12／HiveOS 套件保留既有 SM86 主映像、舊驅動原生映像與內嵌
CUDA 12.2 原生 SM86 相容 fallback，全程自動選擇，不需手動指定模組或幾何參數。

`-p/--pass` 並非必填；CLI 省略或 HiveOS Pass 留空時會使用相容預設值 `x`。使用者礦池
登入會攜帶有界的 GPU 摘要與礦工版本中繼資料，不處理選用中繼資料的礦池仍維持相容。

本版亦公開 RTX 3080 10GB 合格樣卡設定：功率牆 320 W、顯存鎖定 810 MHz、核心 offset
`+260 MHz`，不使用核心鎖頻；核心 offset 所需的 display 與 Xauthority 參數如上方完整命令。
合格的 RTX 3080 10GB 樣卡在 320 W 功率牆下進行熱卡 60 秒測試，實測為 64.386 MH/s。
此 offset 僅代表該張樣卡，不保證每張 RTX 3080 都能使用；選用設定失敗時，礦工會在安全可恢復
的情況下還原硬體並以已驗證的預設狀態繼續。

RTX 3080 10GB 已使用最終 CUDA 12 二進位，以預設硬體設定及省略 Pass 的最簡使用者命令
連接官方 TLS 真池，達到 `ONLINE`、取得 accepted 工作、沒有 rejected 工作，並完成精確自檢。
RTX 4070 已使用同一 CUDA 12 二進位的最終 HiveOS 套件，在空 Pass 下取得 accepted 工作、
沒有 stale 或 rejected 工作，且通過官方 TLS 真池與 HiveOS 統計。CUDA 13 實體 GPU、其他
上表型號、多 GPU、斷線／failover 注入及長時間運行，本版未重新實測。

HiveOS 請使用 `invminer-0.1.63.tar.gz`；Miner name 填 `invminer`、Hash algorithm 填
`noid`、Template 填 `%WAL%.%WORKER_NAME%`、Pass 可留空，Extra config arguments 預設
留空。官方節點僅為 `eu.innovlab.cc:19601` 或 `hk.innovlab.cc:19601`。

NOID 開發費為有效挖礦時間的 5%。套件不會自行建立或啟用開機服務、cron、排程、登入
啟動項或容器重啟策略；本倉庫僅提供閉源二進位，使用者需自行評估相容性與信任風險。
