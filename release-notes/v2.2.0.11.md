# INVminer v2.2.0.11

Proxima upgrade-6 · Linux / HiveOS / Windows x64 · 0% developer fee.

## Changes

- Lower default CPU use by reducing GPU dispatch overhead and unused monitoring queries, while retaining temperature protection. Default performance and measurement limits are listed below. No pool upgrade is required.
- Optional `--proxima-cpu-mode low` (`-CpuMode low` in the Windows BAT launcher) allows longer batches to reduce CPU wakeups and may trade a little hashrate during job changes. The default remains performance-first; low mode is never selected automatically.

## CPU and hashrate measurements / CPU 与算力实测

Compared with public 2.2.0.10 on the current InnovLab pool, same physical card,
driver, power cap and pool route. CPU is miner process user + kernel time; **100%
means one logical CPU core**, not the whole computer. Hashrate is completed work
over the full measured wall window, including job gaps, not a peak kernel rate
or an earnings forecast.

| GPU / OS / driver / power cap | 2.2.0.10 CPU → default CPU | CPU reduction | Hashrate GH/s |
|---|---:|---:|---:|
| RTX 4090 / Linux / 595.71.05 / 450 W | 12.25% → 4.14% | **66.2%** | 13.329 → 13.520 (+1.43%) |
| CMP 50HX / HiveOS / 610.43.03 / 160 W | 2.63% → 1.96% | **25.3%** | 3.458 → 3.467 (+0.25%) |
| RTX 3070 Ti / Windows / 536.40 / 100 W | 0.483% → 0.334% | **30.9%** | 1.165 → 1.162 (−0.22% raw; baseline drift 2.65%) |

4090: A/B/B/A, four 240-second phases with 45 seconds warmup per phase;
251 Accepted matched durable pool receipts. 50HX: A/B/C/C/B/A, six 180-second
phases, 40 seconds warmup; 312 Accepted matched. A = old default, B = new default,
C = new low-CPU mode. The 4090 baseline had one stale share; the new default had none.
The 50HX comparison had zero rejected/stale shares; neither comparison had rejected shares. These short samples do not establish a universal speedup or
long-term stability.

On 50HX, optional `low` measured **1.57% CPU** (40.3% below 2.2.0.10, 20.1%
below the new default), with **3.466 GH/s** versus the new default's 3.467 GH/s.
Job timing, driver differences and the existing batch/result capacity limits can change or limit this tradeoff. This option is not
an operating-system CPU-percentage cap. No GPU power, clock or fan settings are
changed by the miner.

默认优先保证实池算力，只减少调度和无用查询开销；`balanced` 是默认性能档的参数名。
省 CPU 档需要主动指定 `low`，不是默认设置，也不是 CPU 占比硬限制。上表百分比以
单逻辑核为 100%；低 CPU 模式的收益和少量算力损失取决于显卡、驱动及任务切换。

Linux / HiveOS optional argument:
```text
--proxima-cpu-mode low
```
Windows optional argument:
```bat
start-proxima.bat -Account YOUR_PROXIMA_HOLDER_ID -Worker WORKER -CpuMode low
```
Omit the option to keep the performance-first default. Config files can use
`coin.tuning.cpu_mode = "low"`; an explicit CLI option takes precedence.

Windows used a 300-second prewarm followed by six 150-second A/B/C/C/B/A
phases, excluding 40 seconds warmup per measured phase. All 340 Accepted
(including prewarm) matched the pool, zero rejected/stale. The old-version
baseline drifted 2.65%; **no Windows hashrate gain or attributable regression
is established by this round**. Optional low measured 0.213% CPU and
1.152 GH/s: 55.9% less CPU and 1.10% less work than the old default, or
0.89% less work than the new default. These raw work differences have the
same baseline uncertainty; do not treat them as universal loss bounds.

Windows 默认档 CPU 下降约 30.9%，算力原始差值 −0.22%，小于旧版自身 2.65%
的漂移，不能据此宣称算力提速或回退。低 CPU 档仅手动开启。

## Recommended pools / 多池推荐参数

Ordered multiple pools, automatic reconnect, primary recovery and `rotate` remain supported. Keep this order; repeat `-o` on Linux, or enter one URL per line in HiveOS.

| Region / 区域 | Primary / 主池 | Backup 1 / 备用一 | Backup 2 / 备用二 |
|---|---|---|---|
| Asia / 亚洲 | `stratum+ssl://fast-hk1.innovlab.cc:19701` | `stratum+ssl://fast-hk2.innovlab.cc:19701` | `stratum+ssl://hk.innovlab.cc:19701` |
| Europe / 欧洲 | `stratum+ssl://fast1-ru.innovlab.cc:19701` | `stratum+ssl://fast2-ru.innovlab.cc:19701` | `stratum+ssl://eu3.innovlab.cc:19701` |

```bash
./invminer --coin proxima \
  -o stratum+ssl://fast-hk1.innovlab.cc:19701 \
  -o stratum+ssl://fast-hk2.innovlab.cc:19701 \
  -o stratum+ssl://hk.innovlab.cc:19701 \
  -u YOUR_PROXIMA_HOLDER_ID.WORKER -p x \
  --pool-failover-mode primary --pool-give-up-limit 3 \
  --pool-probe-interval-secs 60 --pool-probe-successes 2
```

The four failover options above restate the defaults. `primary` returns to the preferred pool after successful login/job probes, subject to failure cooldowns. `--pool-failover-mode rotate` stays on a healthy backup and advances when it fails. Multiple entries provide fallback, not simultaneous mining. Mining TLS is encrypted and accepts self-signed pool certificates; download HTTPS verification remains enabled.

以上切换参数即默认值，通常无需额外调整。`primary` 会探测并恢复首选池；`rotate` 在备用池健康时继续挖，不主动切回。多个地址用于故障切换，不是同时挖多个池。

All six listed endpoints received valid shares during final-package qualification.
Linux/HiveOS and Windows primary recovery and rotate retention/wrap were verified using
controlled connection faults. This is functional verification, not an availability
or latency guarantee.

Windows final ZIP BAT start/restart, default/low selection and fault recovery
passed on the physical RTX3070Ti. HiveOS used the official custom installer and
local flight-sheet callbacks; the cloud UI was not operated.

Windows: extract the ZIP and run `start-proxima.bat`. Asia is the default; for Europe:

```bat
start-proxima.bat -Account YOUR_PROXIMA_HOLDER_ID -Worker WORKER -Region europe
```
