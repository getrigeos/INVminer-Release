# INVminer NOID GPU Miner v0.1.43

This release hardens long-running NOID mining and retires unsupported product
paths. Both packages are multi-architecture Linux x86_64 binaries; choose by
host driver compatibility, not GPU model. No proprietary Rust/CUDA source is
included in the archives or this public repository.

> **Binary-only risk:** this release may be incompatible with a particular GPU,
> driver, OS or pool state. Source is not provided, so users cannot independently
> rebuild, audit or patch it and must decide whether to trust the binary and its
> published checksums.

## Recommended command

All visible GPUs, recommended:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0
```

Do not provide threads, nonces-per-thread, or batch parameters. Qualified
models select reviewed defaults; other supported models perform a bounded
first-run auto-tune and save it locally.

Optional RTX 4090 profile qualified on this release:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0 \
  --power-limit 450 \
  --locked-core-clock 2400
```

Hardware controls are optional. If a requested control is unsupported, the
miner warns and continues with verified defaults. A failed partial application
is rolled back in-process where the driver permits it; an incomplete rollback
exits cleanly for service-manager recovery.

| RTX 5090 | `sm_120` | CUDA 13 / 595.84 | Historical physical lane | `159.135 MH/s` | `575 W` | `549.04 / 564.70 W` | default clocks |

The RTX 4070 SUPER per-GPU hashrate is the six-card aggregate divided by six,
not a separate isolated single-GPU benchmark. All six cards selected the same
reviewed module/profile, passed exact self-tests and used one shared user-pool
connection with disjoint search allocation. The release assets were then
rebuilt reproducibly on RTX 4090; therefore the 4070 SUPER row is same-source
device-lane evidence, while the two RTX 4090 rows identify the exact packaged
host binaries.

The exact CUDA 13 package also completed a live RTX 4090 gate with the optional
`450 W / 2400 MHz locked-core` profile. It reached `111.366 MH/s` live total
rate, recorded 66 accepted and zero rejected responses, survived a deliberate
TLS socket reset in the same process, reconnected after the expected three
seconds, and then recorded 40 more accepted with zero rejected responses.

The CUDA 12 host package transparently embeds a reviewed CUDA 13-produced
native `sm_120` module because that instruction path cannot be assembled by the
CUDA 12 toolchain. It links no CUDA 13 runtime. This does not turn the CUDA 12
host package into a CUDA 13 host binary.

## Developer fee

The compiled developer fee is 5% of effective GPU mining time: 95 minutes of
user work followed by a 5-minute fee window. The payout destination is embedded
in the binary and is intentionally not printed in public release material or
normal runtime logs. Fee preparation failure does not stop user mining, and
accounting is based on GPU time rather than raw share-count ratios.

## Reliability and validation

- CUDA 12 passed 48 NOID tests and CUDA 13 passed 49; both release flavors
  passed formatting and clippy with warnings denied.
- Every physically gated GPU passed four CPU/GPU exact vectors and all
  search-result paths before benchmark or pool work began.
- A failed CUDA device is isolated and rebuilt with bounded backoff while
  healthy GPUs continue. Exhausted all-device recovery exits cleanly instead of
  leaving a connected zero-hash process.
- The share-health guard requires either 20 consecutive resolved rejections or
  more than half of a full 100-response window before reconnecting. Sparse and
  stale transition responses do not trigger it.
- Pool reconnect uses bounded exponential backoff. Status is rate-limited and
  per-share, per-job and per-work-slice production logs are absent.
- Exact packaged binaries passed version, native module, GLIBC, archive member,
  private-path, endpoint identity and runtime-log leakage gates. The live log
  contained neither the user identity nor the private developer-fee payout
  identity.
- The original workload on the physical gate host was restored after testing.

## Optional hardware controls

Default clocks remain the general recommendation. `--power-limit`,
`--locked-core-clock`, and `--core-clock-offset` are optional multi-coin
controls. A locked clock and a clock offset are alternative tuning methods and
should not be combined without a card-specific qualification; this is operator
guidance, not a global parser restriction.
