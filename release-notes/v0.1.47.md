# INVminer NOID Miner v0.1.47

v0.1.47 adds an explicit CPU-only NOID mode with runtime-selected packed
AVX-512/AVX2 execution. The default remains GPU-only: without `--cpu-only`,
INVminer creates CUDA workers and never creates a CPU nonce-search pool.

Both assets are multi-architecture Linux x86_64 binaries. Choose the package
by host-driver compatibility, not GPU model. No proprietary Rust/CUDA,
proof-system or hardware-control source is included in this repository or the
release assets.

> **Binary-only risk:** this release may be incompatible with a particular GPU,
> CPU, driver, OS or pool state. Source is not provided, so users cannot
> independently rebuild, audit or patch the miner and must decide whether to
> trust the binary and its published checksums.

Both binaries were linked in an isolated Ubuntu 20.04 / Rust 1.96 builder,
are stripped, require at most `GLIBC_2.30`, and load the NVIDIA Driver API at
runtime rather than linking a CUDA runtime library. Two clean builds of each
flavor were byte-for-byte identical. Each POSIX ustar archive contains only
`README.txt` and `invminer-noid`.

The CUDA 12 asset's native `sm_120` module was produced by CUDA 13.3 because
CUDA 12 cannot assemble that architecture. It does not add a CUDA 13 runtime
dependency to the host executable, but RTX 50 operation still requires a new
enough driver; the physical RTX 5090 evidence used driver 595.84.

## Recommended commands

All visible GPUs:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0
```

CPU-only:

```bash
./invminer-noid \
  --cpu-only \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

Do not provide threads, mining geometry, batch size or ISA flags. Qualified
GPUs select reviewed defaults; other supported models perform a bounded
first-use auto-tune and save it locally. CPU-only mode selects the best
supported AVX-512 or AVX2 backend and all logical CPUs visible to the process.

The normal commands deliberately omit `--state-dir`. INVminer automatically
uses a persistent per-user state location. Managed services may set
`INVMINER_STATE_DIR`, and an explicit absolute `--state-dir` remains optional.

Optional previously qualified RTX 4090 profile:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0 \
  --power-limit 450 \
  --locked-core-clock 2400
```

Default clocks are the general recommendation and were used for all exact
v0.1.47 GPU measurements below. Hardware controls are optional. Unsupported
operations warn and continue at verified defaults; locked-core and offset
tuning should not be combined without card-specific qualification.

## GPU measurements and compatibility evidence

Hashrate is full NOID work rate. The exact v0.1.47 RTX 4090 measurements used
no miner hardware-control arguments, a factory 450 W power limit and a
30-second steady interval. Average/peak power includes only samples at or above
95% GPU utilization.

| GPU | SM | Package / driver | Evidence status | Hashrate | Power limit | Average / peak power | Clock/control state |
|---|---|---|---|---:|---:|---:|---|
| RTX 3080 | `sm_86` | CUDA 12 / 550.78 | Historical physical lane evidence | `42.001 MH/s` | `320 W` | `279.67 / 284.37 W` | default clocks |
| RTX 4070 SUPER ×6 | `sm_89` | CUDA 12 / 535.171.04 | Historical six-GPU physical lane evidence | **`53.450 MH/s per GPU`**; `320.701 MH/s` aggregate | **`220 W per GPU`** | **`219.51 W per GPU` aggregate average; `220.55 W` peak individual** | default clocks |
| RTX 4090 | `sm_89` | CUDA 12 / 580.173.02 | Exact v0.1.47 executable | `117.766 MH/s` total; `117.780 MH/s` kernel | `450 W` | `440.51 / 451.91 W` | default clocks; no hardware arguments |
| RTX 4090 | `sm_89` | CUDA 13 / 580.173.02 | Exact v0.1.47 executable | `114.554 MH/s` total; `114.565 MH/s` kernel | `450 W` | `420.46 / 449.23 W` | default clocks; no hardware arguments |
| RTX 5090 | `sm_120` | CUDA 13 / 595.84 | Historical physical lane evidence | `159.135 MH/s` | `575 W` | `549.04 / 564.70 W` | default clocks |

The RTX 4070 SUPER single-card rate is the six-card aggregate divided by six;
all six cards used one user-pool connection and disjoint nonce domains. The
historical rows prove the listed native lane on that physical card, but are not
presented as a rerun of the v0.1.47 host executable. Cards sharing an embedded
architecture but not listed above are compatible by design and unqualified for
performance. Firmware, driver, cooling, virtualization and board power behavior
can materially change results.

## CPU-only measurements

These measurements ran the exact final binaries and full canonical NOID hash;
they are not reduced-work proxy counters. GPU mode was also checked to ensure
that linking CPU support does not create a CPU mining pool.

| Host class | Package | Selected backend | Logical threads | Full-hash rate |
|---|---|---|---:|---:|
| Zen 4 AVX-512 | CUDA 12 | `avx512bw+vpclmulqdq` | 192 | `32.600 MH/s` |
| Zen 4 AVX-512 | CUDA 13 | `avx512bw+vpclmulqdq` | 192 | `32.796 MH/s` |
| Zen 4 forced lower-ISA gate | CUDA 12 | `avx2+vpclmul` | 192 | `24.581 MH/s` |
| Classic AVX2 generation | CUDA 12 | `avx2+pclmul` | 8 | `836.089 KH/s` |

The forced lower-ISA row validates dispatch correctness on the same modern
host; it is not a prediction for every AVX2 CPU. CPU power was not captured and
is therefore not claimed.

## Reliability and current pool gate

- The exact CUDA 13 executable completed CPU/GPU exact self-test, established a
  WebPKI-verified TLS session through the authorized redacted compatibility
  gate, stayed alive after the only socket was forcibly closed, and produced
  three connection/reconnect events from one initial event.
- During this final v0.1.47 window, the compatibility service accepted the TLS
  session but supplied no mining job; the production InnovLab edge was also
  TLS-unavailable. Therefore this run produced **no v0.1.47 accepted-share
  sample**. Earlier accepted-share results are intentionally not relabeled as
  exact v0.1.47 evidence. Users require an operational pool job stream to mine.
- Pool reconnect uses bounded exponential backoff with jitter. Share health
  requires at least 20 consecutive resolved rejections or a majority of a full
  100-response window; stale and expired responses do not count as rejects.
- Returned CUDA errors rebuild only the affected device with bounded backoff.
  Exhausted rebuilds exit nonzero so a service manager can create a fresh
  driver context; an in-flight watchdog covers a stuck synchronous CUDA call.
- Continuous per-device thermal control limits at 92 C and pauses at 95 C with
  hysteretic recovery. A stale sensor pauses only the affected device.
- Runtime logs and status output are bounded and rate-limited. Per-share/job
  hot-path templates, exact developer-fee transitions and payout identities are
  absent. Hashrate automatically selects H/s through EH/s units.

## Developer fee

The compiled developer fee is 5% of effective mining time under a 95/5 cycle.
Integrity-checked progress is persisted so restarts neither reset nor front-load
the schedule. Waiting, preparation failure and unavailable fee work are not
charged. The payout destination is embedded and intentionally absent from
public material and normal runtime logs. User and fee raw share counts need not
form a 95:5 ratio when their sessions receive different variable difficulties.

## Validation summary

- CUDA 12 passed 6 library and 50 executable release tests; CUDA 13 passed 7
  library and 50 executable release tests. Both passed strict Clippy with
  warnings denied.
- Two independent clean builds of each flavor matched byte-for-byte.
- Exact CPU-only binaries passed scalar-gold, zero-target, maximum-target and
  recorded-hit search checks on AVX-512 and classic AVX2 hosts.
- Version/help surface, archive members, `GLIBC_2.30` ceiling, runtime CUDA
  loading, internal paths, credentials, legacy branding, payout identity,
  fee-timing templates and high-rate log templates passed static gates.
- The original workloads on all physical gate hosts were restored after tests.
