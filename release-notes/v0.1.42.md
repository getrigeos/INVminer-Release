# INVminer NOID GPU Miner v0.1.42

This is the first INVminer-branded Linux x86_64 release. Both packages are
multi-architecture binaries; choose by host driver compatibility, not GPU
model. No proprietary Rust/CUDA source is included in the archives or this
public repository.

Both binaries were linked in an Ubuntu 20.04 / Rust 1.96 isolated builder,
are stripped, and require at most `GLIBC_2.30`. The downloadable archives use
plain POSIX ustar with no host extended attributes.

## Recommended command

All visible GPUs, recommended:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0
```

Do not provide threads, nonces-per-thread, or batch parameters. Qualified
models select reviewed defaults; other supported models perform a bounded
first-run auto-tune and save it locally.

The CUDA 12 host package transparently embeds a reviewed CUDA 13.3-produced
native `sm_120` module because that instruction path cannot be assembled by the
CUDA 12 toolchain. It links no CUDA 13 runtime. This does not turn the CUDA 12
host package into a CUDA 13 host binary.

The exact CUDA 13 binary was also tested on Driver 550 and correctly exited
before CUDA context creation with guidance to use the CUDA 12 package. Its
native `sm_120` path was subsequently gated on RTX 5090 / Driver 595.84. For
RTX 4090, the operator authorized reuse of the prior Driver 580.173.02 result:
v0.1.42 embeds the byte-identical, build-time SHA-locked SM89 module
`2af84112e16237c358165ebdc43eaeba96d0280fd21962f0b7c092ed1f9be5cd`
and the unchanged `512/2` release profile. The reused benchmark measured
`101.771 MH/s` total, `101.809 MH/s` kernel rate and approximately `341 W`
average power at default clocks. This is frozen-lane evidence rather than an
exact v0.1.42 host-binary rerun.

## Developer fee

The compiled developer fee is 5% of effective GPU mining time: 95 minutes of
user work followed by a 5-minute fee window. The fixed developer address is
`o15xzyn40khzu6m3vvmw8mthg80j3dkpsc76w9ne2rmzrlvqw5035scwqzaj`. Fee
preparation failure does not stop user mining, and accounting is based on GPU
time rather than raw share-count ratios.

## Reliability and validation

- 42 NOID tests and 25 shared-backend tests passed; CUDA-feature clippy passed
  with warnings denied.
- Every tested GPU passed four CPU/GPU exact vectors and all search-result
  paths before benchmark work began.
- Six RTX 4070 SUPER cards selected the same reviewed `sm_89` module, restored
  all six auto-tune entries from cache, and used the one-connection/disjoint
  allocator implementation covered by the concurrency tests.
- Binary identity, canonical InnovLab endpoint, private-path scan, legacy
  runtime-namespace scan, source-free archive boundary, GLIBC ceiling, and
  checksums were verified on the exact packaged files.
- The exact CUDA 12 archive binary completed a live gate through the authorized,
  WebPKI-verified `release-gate-compat` path: 275 shares were submitted, 269 were
  accepted and none were rejected. The remaining submissions were pending or
  expired across job transitions and controlled shutdown, so the rejection rate
  among resolved pool responses was `0/269`.
- During the same gate, the six-card live rate stabilized at approximately
  `314.3–315.9 MH/s` total (`315.9–316.8 MH/s` kernel rate).
- A deliberate TLS socket break produced one transport reconnect with the
  expected three-second first backoff. Connections increased from one to two
  and accepted shares increased from 145 to 190 within the following 15-second
  observation window, without restarting the miner process.
- The exact CUDA 13 archive binary passed all four CPU/GPU vectors and every
  search-result path on RTX 5090 / Driver 595.84, selecting the reviewed
  `448/2` release profile without user geometry parameters. Its 30-second
  benchmark measured `159.135 MH/s` total and `159.158 MH/s` kernel rate.
- The RTX 5090 live gate produced 64 accepted shares with zero rejected and no
  reconnect. Warm full-job windows settled at approximately
  `154.49–155.67 MH/s`. Across a 20-sample live power series, the 18 samples
  reporting full GPU utilization averaged `552.66 W`, with `578.94 W` peak and
  `78 C` peak temperature. Transient job-boundary samples were retained in the
  evidence but excluded from that full-load average.
- The RTX 4090 support claim is additionally anchored to the unchanged SM89
  module digest and `512/2` profile above. Its reused physical gate was run on
  Driver 580.173.02 at the default 450 W wall and default clocks; no
  overclocked result is used in this table.

## Optional hardware controls

Default clocks are recommended for this release. `--power-limit`,
`--locked-core-clock`, and `--core-clock-offset` remain optional. A locked clock
and a clock offset are alternative tuning methods and should not be combined
without a card-specific qualification. Unsupported controls warn and continue
with default mining; failed tuning is rolled back in-process where the driver
permits it.
