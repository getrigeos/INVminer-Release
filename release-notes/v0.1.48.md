# INVminer NOID Miner v0.1.48

v0.1.48 adds a dedicated shared-GF8 CUDA 12 kernel for Turing/CMP `sm_75`.
Matched stock-clock A/B testing improved CMP 40HX by 20.9%, CMP 50HX by
19.6%, and RTX 2080 Ti by 18.3%. The CPU-only AVX-512/AVX2 mode and all
SM86/SM89/SM120 kernels remain unchanged. Without `--cpu-only`, INVminer
creates CUDA workers and never creates a CPU nonce-search pool.

Both assets are multi-architecture Linux x86_64 binaries. Choose the package
by host-driver compatibility, not GPU model. No proprietary Rust/CUDA,
proof-system or hardware-control source is included in this repository or the
release assets.

> **Binary-only risk:** this release may be incompatible with a particular GPU,
> CPU, driver, OS or pool state. Source is not provided, so users cannot
> independently rebuild, audit or patch the miner and must decide whether to
> trust the binary and its published checksums.

Both binaries were linked in an isolated Ubuntu 20.04 / Rust 1.96 builder,
are stripped, require at most `GLIBC_2.30`, and load the NVIDIA Driver API at
runtime rather than linking a CUDA runtime library. Two clean builds of each
flavor were byte-for-byte identical. Each POSIX ustar archive contains only
`README.txt` and `invminer-noid`.

The CUDA 12 asset's native `sm_120` module was produced by CUDA 13.3 because
CUDA 12 cannot assemble that architecture. It does not add a CUDA 13 runtime
dependency to the host executable, but RTX 50 operation still requires a new
enough driver; the physical RTX 5090 evidence used driver 595.84.

## Recommended commands

All visible GPUs:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0
```

CPU-only:

```bash
./invminer-noid \
  --cpu-only \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

Do not provide threads, mining geometry, batch size or ISA flags. Qualified
GPUs select reviewed defaults; other supported models perform a bounded
first-use auto-tune and save it locally. CPU-only mode selects the best
supported AVX-512 or AVX2 backend and all logical CPUs visible to the process.

The normal commands deliberately omit `--state-dir`. INVminer automatically
uses a persistent per-user state location. Managed services may set
`INVMINER_STATE_DIR`, and an explicit absolute `--state-dir` remains optional.

Optional previously qualified RTX 4090 profile:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0 \
  --power-limit 450 \
  --locked-core-clock 2400
```

Default clocks are the general recommendation and were used for all new
v0.1.48 SM75 measurements below. Hardware controls are optional. Unsupported
operations warn and continue at verified defaults; locked-core and offset
tuning should not be combined without card-specific qualification.

The RTX 4070 SUPER single-card rate is the six-card aggregate divided by six;
all six cards used one user-pool connection and disjoint nonce domains. The
historical rows prove the listed native lane on that physical card, but are not
presented as a rerun of the v0.1.48 host executable. Cards sharing an embedded
architecture but not listed above are compatible by design and unqualified for
performance. Firmware, driver, cooling, virtualization and board power behavior
can materially change results.

CMP 40HX, CMP 50HX and RTX 2080 Ti load the same reviewed native shared-GF8
`sm_75` module and independently select `384/2`. Reverse-order matched A/B
means were `1.4605→1.766 MH/s`, `2.430→2.9065 MH/s`, and
`3.0785→3.6415 MH/s`, respectively. The starred CMP 50HX power figure was
captured from the same integrated source and geometry at `2.911 MH/s`; the
exact final Focal executable was then rerun at `2.914 MH/s`. These cards must
use the CUDA 12 package: CUDA 13 has no production `sm_75` lane.

## Reliability and live-pool gate

- The unchanged CUDA 13 lanes retain the v0.1.47 CPU/GPU exact self-test and
  live-pool qualification evidence: **99 accepted, 2 stale and 0 rejected**.
- In that historical CUDA 13 gate, forcing the only pool socket closed raised
  reconnect count to one, kept the process alive and advanced accepted from 56
  to 57. The stale total includes the deliberately interrupted session.
- Per-share INFO logs are intentionally absent. The acceptance figures were
  read from the loopback `/stats` `shares` object rather than inferred from log
  line counts.
- The exact final v0.1.48 CUDA 12 executable passed the authorized redacted
  compatibility-pool recovery gate on CMP 50HX. Before the forced socket loss
  it had **1 accepted**; the same PID reconnected once and increased to
  **3 accepted**, with **0 stale and 0 rejected**. Endpoint and test identity
  are intentionally not public.
- The RTX 2080 Ti and CMP 40HX recovery figures from v0.1.47 remain historical
  transport evidence; the v0.1.48 change is confined to the reviewed SM75
  device kernel and does not alter pool handling.
- Pool reconnect uses bounded exponential backoff with jitter. Share health
  requires at least 20 consecutive resolved rejections or a majority of a full
  100-response window; stale and expired responses do not count as rejects.
- Returned CUDA errors rebuild only the affected device with bounded backoff.
  Exhausted rebuilds exit nonzero so a service manager can create a fresh
  driver context; an in-flight watchdog covers a stuck synchronous CUDA call.
- Continuous per-device thermal control limits at 92 C and pauses at 95 C with
  hysteretic recovery. A stale sensor pauses only the affected device.
- Runtime logs and status output are bounded and rate-limited. Per-share/job
  hot-path templates, exact developer-fee transitions and payout identities are
  absent. Hashrate automatically selects H/s through EH/s units.

## Developer fee

The compiled developer fee is 5% of effective mining time under a 95/5 cycle.
Integrity-checked progress is persisted so restarts neither reset nor front-load
the schedule. Waiting, preparation failure and unavailable fee work are not
charged. The payout destination is embedded and intentionally absent from
public material and normal runtime logs. User and fee raw share counts need not
form a 95:5 ratio when their sessions receive different variable difficulties.

## 实测摘要

- CMP 40HX：`1.776 MH/s`，110 W 墙，平均/峰值 `108.54 / 112.14 W`；
  CMP 50HX：精确正式二进位 `2.914 MH/s`，160 W 墙，同源码功耗轮
  `157.66 / 163.08 W`；RTX 2080 Ti：首启/缓存 `3.722 / 3.697 MH/s`，
  250 W 墙，平均/峰值 `239.85 / 256.36 W`。三张 SM75 卡均为默认频率、自动 `384/2`，只能使用
  CUDA 12 包；CUDA 13 包没有默认 SM75 生产 lane。
- RTX 4090、450 W、默认频率、无硬件控制参数：CUDA 12 为
  `117.766 MH/s`、平均/峰值 `440.51 / 451.91 W`；CUDA 13 为
  `114.554 MH/s`、平均/峰值 `420.46 / 449.23 W`。
- RTX 4070 SUPER 六卡历史实机证据：**单卡 `53.450 MH/s`，单卡功耗墙
  `220 W`，单卡平均 `219.51 W`，单卡峰值 `220.55 W`**；六卡共用一个
  用户矿池连接且 nonce 空间互不重叠。该数据没有冒充为 v0.1.48 重测。
- RTX 3080 历史实机为 `42.001 MH/s`，RTX 5090 历史实机为
  `159.135 MH/s`。相同 SM 架构的未列型号仅表示设计兼容，不承诺算力。
- 192 逻辑线程 Zen 4：AVX-512 为 `32.600 MH/s`（CUDA 12 包）和
  `32.796 MH/s`（CUDA 13 包）；强制 AVX2+VPCLMUL 为 `24.581 MH/s`。
  8 线程经典 AVX2+PCLMUL 主机为 `836.089 KH/s`。

## 稳定性、费用与已知边界

- 精确 v0.1.48 CUDA 12 正式二进位在 CMP 50HX 通过经授权、地址不公开的
  兼容池恢复门禁：强制断线前 `1 accepted`，相同 PID 重连一次后增长到
  `3 accepted`，全程 **0 stale、0 rejected**。测试端点和 worker 不公开。
- CUDA 13 以及 RTX 2080 Ti/CMP 40HX 的连接恢复仍沿用 v0.1.47 已通过的历史
  实机证据；v0.1.48 只更改 SM75 device kernel，不更改矿池连接实现。
- 新版按商用日志规范取消逐 share INFO 输出；上述计数来自本机 `/stats` 的
