# INVminer NOID Miner v0.1.49

v0.1.49 is a maintenance release for the NOID GPU and CPU-only runtimes, with
updated Linux CUDA 12 and CUDA 13 packages.

Both downloads are multi-architecture Linux x86_64 binaries. Choose by host
driver compatibility, not by GPU model. This public repository and the release
assets contain no proprietary Rust/CUDA, proof-system, or hardware-control
source.

> **Binary-only risk:** this release may be incompatible with a particular GPU,
> CPU, driver, OS, or future pool state. Source is not provided, so users cannot
> independently rebuild, audit, or patch it and must decide whether to trust the
> executable and the published checksums.

Both executables were linked in a digest-pinned CUDA 12.2.2 / Ubuntu 20.04
builder with Rust 1.96.0. Their maximum required GNU C Library symbol is
`GLIBC_2.30`; CUDA and NVML are loaded through the host driver rather than
linked as runtime libraries. Two clean builds of each flavor were byte-for-byte
identical. Each POSIX ustar archive contains only `README.txt` and the stripped
`invminer-noid` executable.

The CUDA 12 package includes a reviewed native SM120 image even though its host
compatibility boundary is CUDA 12. Blackwell operation still requires an
SM120-capable driver. CUDA 13 deliberately has no SM75 lane; CMP 40HX, CMP 50HX,
RTX 2080 Ti, and other SM75 cards must use CUDA 12.

## Recommended commands

All visible GPUs:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

One selected GPU:

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME \
  --device 0
```

CPU-only:

```bash
./invminer-noid \
  --cpu-only \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

Do not provide GPU geometry, CPU threads, batch size, or ISA flags. Qualified
GPUs select reviewed defaults; other recognized cards use a bounded first-run
auto-tune and save the result in the automatic per-user state directory. The
normal command intentionally omits `--state-dir`; an explicit absolute override
remains optional.

Hardware controls are optional and disabled by default. The current RTX 4070
gate used its default 200 W board cap and no clock arguments. An unsupported
optional control operation warns and continues at verified defaults; do not
combine clock controls without card-specific qualification.

|---|---|---|---|---:|---|---|---|
| RTX 4070 | `sm_89` | CUDA 12 | 580.178.04 | Yes | default 200 W cap; no clock arguments | required all-GPU command above | native module loaded; exact self-test, accepted shares, and forced reconnect passed |

RTX 30-series (`sm_86`), other RTX 40-series (`sm_89`), and RTX 50-series
(`sm_120`) lanes remain architecture-compatible. Turing/CMP (`sm_75`) remains
available only in CUDA 12. These other models were not rerun with the exact
v0.1.49 host executable, so this release makes no model-specific performance
claim for them. Multi-GPU shared-connection and disjoint-search behavior remains
covered by deterministic tests but was not physically rerun on the single-card
release host.

## Reliability evidence

- Both exact packages passed CPU/GPU bit-exact self-tests on the RTX 4070 before
  mining. CUDA 12 selected its reviewed SM89 lane; CUDA 13 selected its separate
  reviewed SM89 lane.
- The canonical InnovLab endpoint returned connection refused from the release
  host during this gate. Under the standing release policy, the authorized
  redacted compatibility endpoint was used with WebPKI verification. Its actual
  address and test identity are intentionally absent from public material.
- CUDA 12 reached 16 accepted, 1 stale, and 0 rejected shares. The stale share
  accompanied an intentionally destroyed TLS socket; the same process restored
  one user connection, incremented its reconnect counter, and continued
  accepting shares.
- CUDA 13 reached 8 accepted, 0 stale, and 0 rejected shares through the same
  authorized compatibility gate.
- CUDA 12 passed 6 library and 50 executable tests; CUDA 13 passed 7 library and
  50 executable tests. Both passed formatting and strict Clippy checks with
  warnings denied.
- Runtime logs remain bounded and rate-limited. Per-share/job templates,
  developer-fee payout identity, exact fee transitions, credentials, private
  endpoints, private builder paths, and legacy branding are absent from the
  package boundary.

## Developer fee and process behavior

The compiled developer fee is 5% of effective mining time under a 95/5 cycle.
Waiting, preparation failures, and unavailable fee work are not charged. The
payout destination is embedded and intentionally absent from public material
and normal runtime logs.

The executable runs only when explicitly launched. Extracting or running this
package does not install or enable a systemd service, cron job, scheduled task,
login/startup item, registry Run key, or container restart policy.

# INVminer NOID v0.1.49（中文说明）

v0.1.49 是 NOID GPU 与 `--cpu-only` 运行时的维护版本，更新了 Linux CUDA 12
与 CUDA 13 发布包。

本次提供两个 Linux x86_64 多架构二进制，请按驱动环境而不是显卡型号选择：

- CUDA 12：面向 535 时代及更广兼容环境，包含 `sm_75/sm_86/sm_89/sm_120` 与 fallback；
- CUDA 13：要求 Driver API 13.0 / Linux 580+，包含 `sm_86/sm_89/sm_120`，不支持 SM75。

推荐命令：

```bash
./invminer-noid \
  --pool stratum+ssl://stratum.innovlab.cc:19601 \
  --worker YOUR_NOID_ADDRESS.RIG_NAME
```

不要指定 GPU 几何、CPU 线程、batch 或 ISA。正常使用无需添加 `--state-dir`；程序会自动选择
每用户持久化目录。硬件控制默认关闭，本次 RTX 4070 双包实测使用默认 200 W 功耗墙且未传入
时钟参数。

两个精确二进制均在 RTX 4070 / Driver 580.178.04 上加载原生 SM89 模块并通过 CPU/GPU
逐位自测。正式 InnovLab 端点在该测试机上返回拒绝连接，因此按既有发布规则改用已授权且不公开
地址的 WebPKI 兼容门禁：CUDA 12 获得 16 accepted、1 stale、0 rejected，并在主动断开唯一 TLS
连接后由同一进程恢复并继续 accepted；CUDA 13 获得 8 accepted、0 stale、0 rejected。

用户无法独立重建、审计或修补，应自行评估信任与兼容风险。

程序只有在用户显式运行时才启动；解压或执行不会自行安装或启用系统服务、计划任务、登录启动项、
